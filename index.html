03 / 项目手册

业务流程与状态机

审批结果、实际交接与设备档案状态是不同概念，不能互相替代。

业务规则执行要求
预约冲突同一设备有效占用区间不得重叠；正式预约号排除自身；NASR 请求 ID 幂等。
实际领出整单领出；真实管理员审批同意后才形成实际事件。
实际归还允许一台或多台分次归还；同单重复、跨单设备必须阻断。
部分归还父预约保持 CHECKED_OUT；逐台已归还设备释放预约资源和实物占用；全部归还才 RETURNED。
维修异常归还立即建立维修限制；档案同步确认维修中后，再由管理员改回在库并成功同步即可解除，不设维修审批模块。
过期未领出按原计划结束释放；已领出按预计归还释放预约资源，但实物仍未归还，禁止重复实际领出。
提前领出YY55 测试提前领出被允许；上线前确认是否符合企业制度及冲突保护。
真实事件时间以可信审批操作记录为准，表单领用/归还日期单独保留。
权限设备管理员白名单、流程身份、实例引用一致；不信任用户可编辑字段。
审批并发风险

两次读校验加异步写并不自动保证并发互斥。上线前必须补验两个同时审批的冲突预约、重复回调、事务回滚及补偿。

服务注册、连接器与自动化

区分写业务回调、只读看板及状态查询；不要混用鉴权或在浏览器保存密钥。

接口组（网关前缀 /yida/v1）用途鉴权
reservations/validate, confirm预约校验及确认HMAC
reservations/approve-validate, approve-check审批前校验 / 同意后即时同步HMAC
reservations/release, reject-sync取消释放 / 驳回同步HMAC
reservations/checkout-validate, checkout领出前校验 / 实际领出HMAC
returns/pending-devices, validate, complete待归还设备 / 校验 / 实际归还HMAC
returns/status领用及预约累计归还状态查询X-Query-Key
dashboard/gantt甘特与可预约时段只读查询X-Gantt-Key
checkouts/validate, confirm, approve旧兼容接口；当前闭环不用HMAC

HMAC 为 HMAC-SHA256；旧服务注册使用 form-urlencoded，签名字段 __hmacSha256，canonical 按非签名参数值去重、排序后用 $ 拼接（以网关现行实现为准）。NAS 内部接口使用 X-API-Key。所有密钥只由管理员在服务端读取。

节点 / 规则服务参数与触发注意
预约审批同意 R12approve-check: bookingId, approvalResult=approved, yidaInstanceId, requestId要求真实流程实例；仅最终同意后调用；未传实例有旧兼容行为，不应作为正式强校验路径
领出提交及审批同意前checkout-validate: bookingId=原预约单号, deviceCodes=领出子表编号阻断不合法业务
领出结束同意checkout: bookingId, checkoutInstanceId=#{formInstId}, checkoutNo, requestId=领用单号历史实测成功；实例是否等同流程 ID 必须按接口核验
归还提交及审批同意前returns/validate: checkoutNo=原领用单号, deviceCodes=归还编号不要直接传关联组件多层对象
归还结束同意returns/complete: yidaInstanceId=#{formInstId}, requestId=归还单号只在同意时同步；实际事件幂等
预约驳回reject-sync核实 COMPLETED/disagree；拒绝节点配置仍需完整现场验收

    print('device counts:',c.execute('SELECT status, count(*) FROM reservation_devices GROUP BY status').fetchall())

备份、恢复、升级与数据留存

数据库位于 NAS 持久化目录，而非仅在容器可写层中。Docker 容器不是备份。

一致性备份示例（NAS 容器，管理员先确认空间及备份路径权限）

python - <<'PYCODE'
from pathlib import Path
from datetime import datetime
import sqlite3, shutil, hashlib, os
os.umask(0o077)
root=Path('/app/data/backups')
root.mkdir(mode=0o700,parents=True,exist_ok=True)
dst=root/datetime.now().strftime('%Y%m%d-%H%M%S-%f')
dst.mkdir(mode=0o700)
with sqlite3.connect('file:/app/data/reservations.db?mode=ro',uri=True,timeout=30) as s:
    with sqlite3.connect(str(dst/'reservations.db')) as d:
        s.backup(d)
        assert d.execute('PRAGMA quick_check').fetchone()[0]=='ok'
shutil.copy2('/app/app/main.py',dst/'main.py')
for p in dst.iterdir():
    print(p.name,hashlib.sha256(p.read_bytes()).hexdigest())
print('backup:',dst)
PYCODE

此命令新增备份文件，不改业务数据。备份位于同一 NAS，仍需加密复制到独立存储，避免磁盘故障或勒索导致主库和备份同时丢失。另行保护 compose、环境变量、网关文件、Nginx、FRP 及宜搭导出配置；密钥备份须加密且仅授权人员可读取。运行中的 SQLite 不应只用普通 cp 复制单个主库文件而忽略 WAL。

恢复及回滚原则

  1. 明确故障组件与最近正常版本，暂停新增业务及同步任务，记录回滚前的真实数据和审批状态。
  2. 前端问题优先恢复最近已验收且与后端兼容的三个页面文件，保留后端和连接器；网关问题按对应备份恢复 api.py/config.py/nas.py/Nginx，先 nginx -t 再重载；NAS 问题优先恢复代码而非覆盖数据库。
  3. 仅在确认数据库损坏或必须恢复时，停容器并隔离当前 DB、WAL、SHM 文件；先在独立目录恢复备份并检查完整性，核对备份之后发生的真实业务，审批后再执行受控切换。
  4. 重启目标服务，验证健康、只读查询、原有签名接口及测试流程；记录实际 SHA256、时间、执行人、影响范围及验收人。
禁止直接清空数据

不要为了节省空间定期删除 reservations、reservation_devices、processed_events 或审计事件。设备预约数据量通常较小，实际保留期限应由企业质量管理、审计和合规要求决定。优先备份与归档；删除需审批、离线测试、可恢复且不破坏幂等及关联。

权限、安全与审计

内部运维资料含网络拓扑和表单标识，仅限授权人员。

  • 密钥由服务端管理，禁止写入 JSX、页面 JS、CSS、浏览器存储、聊天或截图。历史配置截图曾有凭据暴露风险，正式上线前协调轮换相关密钥并更新对应服务端账号。
  • 外部入口使用 HTTPS；检查 Nginx、云安全组和 FRP 暴露范围，仅授权管理来源可访问运维端口。不能单凭 X-Gantt-Key 认为已有细粒度员工权限。
  • R15.3-business 已允许业务必要姓名、部门、项目编号进入看板；报告称不返回手机号、员工内部 ID、管理员字段。共享 X-Gantt-Key 仅为应用级凭据，不能证明访问者角色；若需按个人或部门控制详情，须增加可信身份与授权检查。
  • SQLite 和备份目录最小权限；维护账号和业务审批账号分离。禁止将数据库、环境配置或完整日志公开分享。
  • API Key、Gantt Key、Query Key、HMAC 密钥及钉钉应用凭据分别盘点，轮换时记录依赖、短期兼容策略、撤销及验证。
  • 保留业务原始记录和可信审批凭证；实际领出归还时间、状态变更及人工修复必须可追溯。
